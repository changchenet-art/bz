# 창체넷 네이버 블로그 자동 발행

주 2~3회 블로그 발행을 위한 원고 저장소와 발행 스크립트입니다.

## 폴더 구조

```
blog/
├── posts/      발행 원고 (YYYY-MM-DD_섹션_주제.md)
├── covers/     이달의 대문 이미지 (YYYY-MM_주제/)
├── scripts/    naver_publish.py — 네이버 블로그 글쓰기 API 발행
├── tools/      창체넷_블로그대문_생성기.html — 대문 제작 도구
└── README.md
```

## 네이버 블로그 카테고리

| 상위 | 하위 |
|---|---|
| 창체넷 소식 | 언론 · **소식** · 공지 및 모집 |

블로그 글은 「창체넷 소식 > 소식」에 올린다. 언론 보도 스크랩은 '언론', 사업 공고와
모집 안내는 '공지 및 모집'으로 나눈다. 원고 front matter `category:` 에 적는다.

## 발행 현황

| 원고 | 코너 | 상태 | 날짜 |
|---|---|---|---|
| 2학기 창체 시간, 탄소중립 수업 이렇게 채워보세요 | — | draft | — |
| 길어진 여름, 짧아진 봄과 가을 | 이달의 대문 9월 | **발행 완료** | 2026-09-05 |
| 함께 나아가는 길 ① 너는 네 삶을 바꿔야 한다 | 함께 나아가는 길 | 예약 | 2026-09-12 |
| 환경위기시계 9시 34분, 1년 새 41분 | 오늘의 픽 환경뉴스 ① | 예약 | 2026-09-11 |
| 올해 단풍, 언제 왔나요 | 이달의 대문 10월 | 예약 | 2026-09-30 |

`status` 는 네 단계다 — `draft`(작성 중) → `approved`(승인) → `scheduled`(예약 확정)
→ `published`(발행 완료). 발행 스크립트는 `approved`·`scheduled` 만 올리고,
`published` 원고는 중복 발행을 막기 위해 거부한다.

## 발행 로테이션

| 요일 | 섹션 | 대상 독자 |
|------|------|-----------|
| 월요일 | 📚 교육 콘텐츠 소개 | 교원, 교육 담당 기관 |
| 수요일 | 🌱 환경·기후 교육 ↔ 🌊 해양교육 (격주 교대) | 교사, 학부모 |
| 금요일 | 🏢 창체넷 소식 | 협력 기관, 교육청, 학교 |

## 「이달의 대문」 코너

매달 대문 이미지를 바꾸고, 그 그림에 담긴 환경 이야기를 같은 달 포스팅으로 함께 내보내는 연재입니다.

1. 그 달의 주제를 정한다 (계절·기후 이슈 중심).
2. 주제에 맞는 사진·그림을 고르고 아래 스크립트로 타이틀 이미지(966×380)와
   메뉴 위젯(170×90)을 만든다. 브라우저에서 직접 조정하려면 `blog/tools/창체넷_블로그대문_생성기.html`.

   ```bash
   python3 blog/scripts/make_cover.py \
       --image 사진.jpg --label "이달의 대문  ·  2026년 10월" \
       --title "올해 단풍, 언제 왔나요" --out blog/covers/2026-10_단풍/ --crop-top 0.75
   ```

   `--crop-top` 은 사진에서 잘라낼 세로 위치(0=위, 1=아래)다. 0.35·0.55·0.75 정도로
   몇 장 뽑아 보고 고르면 빠르다.
3. 결과물을 `covers/YYYY-MM_주제/` 에 저장한다.
4. 같은 주제로 원고를 쓰고 front matter의 `series: "이달의 대문"`, `cover:` 에 이미지 경로를 적는다.
5. 네이버 타이틀 이미지를 교체하고 원고를 발행한다.

| 월 | 주제 | 폴더 |
|---|---|---|
| 2026-09 | 길어진 여름, 짧아진 봄과 가을 | `covers/2026-09_길어진여름/` |
| 2026-10 | 올해 단풍, 언제 왔나요 | `covers/2026-10_단풍/` |

대문 이미지와 사진 원본은 구글 드라이브 「창체넷_블로그」 폴더에도 함께 둔다
(01_사진자산 · 02_이달의대문 · 03_원고).

## 「오늘의 픽 환경뉴스」 코너

🌱 환경·기후 교육 섹션 안에 두는 뉴스 큐레이션입니다. 매일 쏟아지는 환경 뉴스 중
하나를 골라 교실에서 쓸 수 있게 풀어 씁니다. 분량 1,500~2,300자 — 국내와 국외를
함께 다루는 회차는 길어진다.

고정 구성 — ① 오늘의 픽(무슨 일이 있었나) ② 왜 이 뉴스를 골랐나 ③ 배경·맥락
④ 용어 정리 ⑤ 교실에서 나눌 이야기 3~4가지 ⑥ 출처.

**수치는 반드시 검색으로 확인하고 쓴다.** 확인하지 못한 내용은 빼고, 무엇을 확인했고
무엇을 뺐는지 front matter `fact_check:` 에 남긴다. 뉴스 요약은 사실과 해석을 섞기 쉬워
이 코너에서 특히 위험하다.

| 회차 | 제목 | 다룬 뉴스 |
|---|---|---|
| ① | 환경위기시계 9시 34분, 1년 새 41분 | 환경재단·아사히글라스재단 「2026 환경위기시계」 |

## 「함께 나아가는 길」 코너

🏢 창체넷 소식 섹션 안에 두는 기록형 연재입니다. 사업 소식과 달리 대표의 목소리로 씁니다.

담는 것 — **자아성찰**, **함께 나누고 싶은 책이나 이야기**, **만난 사람들**.

분량은 **1,500~2,200자**로 일반 포스팅(1,200~1,500자)보다 길게 잡습니다. 짧게 끊어 쓰는
문체라 줄 수가 많고, 작품 두 편을 엮으면 그 아래를 채우는 데 자리가 필요합니다.

문체는 카드뉴스처럼 씁니다.

- 한 줄을 짧게 끊고 빈 줄로 호흡을 준다. 문단 안 줄바꿈은 `<br>`로 그대로 살아난다.
- 강조는 `**굵게**` 로 표시한다. 발행 스크립트가 `<b>` 로 바꾼다.
- 실제 사건에서 출발해 문학 작품·명화로 넘어가고, 마지막에 교육 현장의 이야기로 내려온다.
- 사실을 쓸 때는 확인한 것만 쓰고, 본문 끝에 참고한 자료를 한 줄로 밝힌다.
  front matter `sources:` 에도 남긴다.
- 명화는 퍼블릭 도메인 작품을 골라 위키미디어 공용에서 받아 에디터에서 직접 넣는다.

front matter에 `series: "함께 나아가는 길"`, `episode: N` 을 적는다.

| 회차 | 제목 | 엮은 작품 |
|---|---|---|
| ① | 너는 네 삶을 바꿔야 한다 | 네팔 칼라파타르 각료회의 · 릴케 「고대 아폴로의 토르소」 · 브뤼헐 「이카로스의 추락이 있는 풍경」 |

## 원고 형식

`posts/*.md` 는 front matter + 고정 섹션 구조를 따릅니다. 발행 스크립트가 이 구조를
그대로 파싱하므로 섹션 제목(`# 제목`, `# 본문`, `# 해시태그`)은 바꾸지 않습니다.

- 제목: 30자 이내, 검색 키워드 포함
- 본문: 1200~1500자, `■` 로 시작하는 소제목 3~4개
- 강조: `**굵게**` (발행 시 `<b>` 로 변환)
- 해시태그: 10개
- `status`: `draft` → 사용자 확인 후 `approved` → 발행되면 `published`

## 발행 방법

```bash
# 1) 변환 결과만 미리 확인 (토큰 불필요)
python3 blog/scripts/naver_publish.py --dry-run blog/posts/2026-08-27_*.md

# 2) 원고 확인 후 front matter의 status 를 approved 로 변경

# 3) 실제 발행
export NAVER_ACCESS_TOKEN=...      # developers.naver.com 에서 발급한 OAuth 2.0 접근 토큰
export NAVER_CATEGORY_NO=...       # 선택
python3 blog/scripts/naver_publish.py blog/posts/2026-08-27_*.md
```

## 주의사항

- 네이버 블로그 글쓰기 API는 OAuth 2.0 접근 토큰이 필요하며 토큰에는 유효기간이 있습니다.
  만료되면 developers.naver.com 에서 재발급합니다.
- API로는 본문에 이미지를 넣을 수 없습니다. 발행 후 네이버 에디터에서 직접 올립니다.
- 태그는 API 파라미터로 안정적으로 전달되지 않아 본문 끝에 해시태그 문단으로 붙입니다.
- 접근 토큰은 절대 저장소에 커밋하지 않습니다. 환경변수로만 전달합니다.
